How this dashboard works

1 · What this is

A scenario coverage tracker for the payments system. Every unique combination of onboarding deposit, payment setup, plan type, and budget basis is generated as a card. You walk through them, marking each 1st Payment and 2nd Payment as Pass or Fail. Refresh resets everything — that's intentional, so each QA run starts clean. Use Save snapshot if you want to resume later.

2 · The two views

  • Grid — every matching scenario as a card with its attributes, fee, Wise badge (if contractor), and Pass/Fail/Reset buttons for both payment stages. Each card also has a Notes field for Jira IDs or error text.
  • Mind Map — the same scenarios as a collapsible decision tree. Click any branch to expand or collapse. Each branch shows its scenario count and rolled-up Pass / Fail / Pending tallies, so you can spot which paths are healthy and which need attention. Drill all the way to a leaf to mark Pass / Fail right in the tree.

Toggle between them with the Grid / Mind Map switch in the top-right of the coverage summary.

3 · Filtering

Three layers of filters work together. Each layer narrows what you see:

  • Sidebar (left) — dimension filters. Click any chip to require that value. Empty group = "match anything for this dimension." Chips are grouped into Onboarding & Payment Setup and Plan & Budget, with Plan Type split under Employee / Contractor sub-headers.
  • Status quick-filter pills (toolbar) — All · Pending · Partial · Passed · Failed. Each shows a live count. Click one to see only that subset.
  • Search box (toolbar) — free text matches scenario IDs (e.g. GS-0042), attribute labels (Contractor, Paylink), and your notes.

Reset filters (sidebar) clears chip selections but keeps your pass/fail marks. Reset statuses & notes does the opposite.

4 · Marking a scenario

Each scenario has two payment stages — 1st Payment and 2nd Payment — to verify the recurring nature of the payment. Each stage has its own:

  • ✓ Pass — payment ran as expected
  • ✗ Fail — payment did not work; type a note explaining why or paste a Jira ID
  • ↻ Reset — clears that stage back to pending

The card border colour reflects the combined state:

both passed any failed one of two marked nothing marked yet

5 · Fees shown on each card

Computed against a fixed $1,000 sample so the math is consistent:

  • Bank methods (Auto-pay Bank, Paylink Bank) → $5.00 flat
  • Card methods (Auto-pay Card, Paylink Card) → 3% = $30.00
  • Invoicing → 2% = $20.00
  • Contractor plans (Contractor Plan or COR) → additional Wise fee applies badge

6 · Export, Import, Snapshot

  • ⬇ Export CSV — downloads the currently displayed scenarios with their statuses, notes, and computed fees. Filenames include a timestamp so you can keep multiple runs.
  • ⬆ Import CSV — re-applies a previously exported CSV. Matches by scenario ID; unknown IDs are skipped with a toast count. Merges into the current state (does not clear what's already there).
  • Save snapshot (sidebar) — keeps your statuses + notes in this browser. Survives refresh, but must be loaded explicitly with Load snapshot. Clear snapshot removes the saved copy.

Use Export / Import to share work between machines or teammates. Use Snapshot to pause and resume on the same machine.

7 · Business rules baked in

  • Onboarding Deposit = No → no Deposit Frequency. The chip is hidden, and the Mind Map skips that level for those scenarios.

Got 60 seconds? Try this

  1. Click Auto-pay Card in the sidebar, then Contractor Plan. The count drops to 72.
  2. Mark a few 1st Payments as Pass and one 2nd Payment as Fail. Notice the summary and progress bar update live.
  3. Switch to Mind Map. The failed branch lights up red all the way to the root.
  4. Type a note on the failed card. Click ⬇ Export CSV. The note travels with the file.
  5. Refresh the page → everything resets. (Click ⬆ Import CSV to restore from the file you just exported.)
